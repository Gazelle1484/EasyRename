# STEP 2: 設計（構造決定）用 Codex 指示

このAndroidプロジェクトについて、以下の仕様をもとに設計を行ってください。

このSTEPでは **実装・コード生成・ファイル変更は行わないでください**。  
目的は、後続STEPで実装しやすいように、アーキテクチャ、パッケージ構成、クラス設計、データフローを明確にすることです。

---

## 前提

- アプリ種別: Androidアプリ
- 対応方針: Android 33対応
- 開発言語: Kotlin
- アーキテクチャ: MVVM + Repository パターン
- 対象: スマホ内部ストレージ内のユーザー選択ディレクトリ
- ストレージ操作: Android 33の制約を考慮し、URIベース / Storage Access Framework前提
- リネーム方式: CSVに定義された候補名をもとに、ユーザーがGUI上で手動マッチングする
- リネーム実行: 1件ずつ手動実行
- 同名ファイルが存在する場合: エラー扱い
- サブディレクトリ対応: 現時点では未定。まずは直下ファイルのみ前提
- CSV仕様: 1行1ルール
- `*` の扱い: 元ファイル名を差し込むワイルドカード

---

## アプリ概要

Android 33対応のファイルリネーム支援アプリとして、スマホ内部ストレージ内のファイルを対象にする。

CSVに定義されたリネーム候補名を読み込み、GUI上で「元ファイル」と「リネーム先」を手動マッチングして、選択したファイルのリネームを実行する。

## 画面構成

以下の画面・UI状態を前提に設計してください。

### 1. ホーム画面

役割:
- リネーム対象ディレクトリを選択
- CSVファイルを選択
- 読み込み状態を表示
- マッチング画面へ進む

表示内容:
- 選択中の対象ディレクトリ名
- 選択中のCSVファイル名
- 読み込み済みファイル数
- 読み込み済みリネーム候補数

### 2. ディレクトリ選択

Android標準のファイルピッカー、またはStorage Access Frameworkを利用する前提。

### 3. CSV選択

Android標準のファイルピッカーを利用する前提。

### 4. リネームマッチング画面

役割:
- 左側にリネーム前ファイル一覧を表示
- 右側にCSV由来のリネーム候補一覧を表示
- 左右から1件ずつ選択
- 両方選択された場合のみ決定ボタンを有効化
- 決定ボタンでリネーム実行

表示状態:
- 未選択
- 選択中
- リネーム済み
- エラー発生

### 5. リネーム結果表示

専用画面ではなく、ダイアログまたはSnackbarでよい。

表示内容:
- 成功メッセージ
- 変更前ファイル名
- 変更後ファイル名
- 失敗時のエラー理由

## データ構造

以下のデータ構造を前提に、必要に応じて追加・整理してください。

### RenameTargetFile

リネーム対象の元ファイル情報。

- id
- displayName
- uri
- size
- lastModified
- isSelected
- isRenamed

### RenameRule

CSVから読み込んだリネーム規則。

- id
- rawPattern
- prefix
- suffix
- hasWildcard
- isUsed

### RenameCandidate

画面右側に表示するリネーム先候補。

- id
- ruleId
- displayName
- rawPattern
- isSelected
- isUsed

### RenamePair

ユーザーが選択したリネーム対応。

- sourceFile
- renameCandidate
- resolvedNewName

### RenameResult

リネーム実行結果。

- beforeName
- afterName
- success
- errorMessage
